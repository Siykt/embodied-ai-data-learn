个性化机器人操作数据回答两个不同问题：机器人是否完成任务，以及完成方式是否满足某项偏好。例如“把杯子放到桌上”是任务目标，“尽量保持杯身竖直”是对执行方式的要求。两条轨迹可以都完成放杯子，却在运动速度、抓取方式或所选对象上表现不同。把这些结果压成一个成功标签，会让模型无法区分任务能力和个性化能力。

**偏好条件**描述在任务目标之外希望采取的行为方式或选择。它可能来自明确指令，也可能来自带有偏好线索的上下文；数据必须保存原始表达、解释后的条件及解释依据。不能仅凭某位操作者的一次动作推断其长期偏好，也不能把机器人恰好采取的行为倒过来标成用户意愿。

## 一、将偏好转为可观察的数据对象

[LIBERO-PeRM](https://arxiv.org/abs/2610.22372)建立受控的个性化操作基准，将偏好分成运动方式、技能选择与用户背景三类。其范围是可以用语言表达、能在 LIBERO 仿真中实现、可以自动衡量且不改变原任务目标的偏好。这种受控范围适合检验模型是否响应了条件，但不代表完整的人类偏好。

| 类型 | 数据问题 | 采集或标注建议 |
| --- | --- | --- |
| 运动偏好 | 路径、速度或与对象距离是否符合条件 | 保存实际轨迹、时间、参考对象和计算单位 |
| 技能偏好 | 是否采用要求的操作方式，如握住杯柄 | 保留接触区域、关键姿态、动作阶段及视觉证据 |
| 用户背景 | 上下文如何影响对象或子任务选择 | 保存原始上下文、对象属性和实际执行的子任务 |

上述例子需要具体定义。所谓“慢一点”要说明相对什么基线、适用于哪段动作；“避开某物体”要说明对象 ID、距离计算方式和有效时间。**偏好满意度**是按已定义规则衡量执行对偏好的满足程度，它是可观测行为指标，并不自动等于用户的主观满意。

标注还应区分可选择的偏好与必须满足的约束。硬件限位、任务必需步骤或独立安全规则应单独记录，不能因偏好权重降低而变成可违反选项。某项要求究竟是偏好还是任务条件，应由任务协议决定，不由模型在评估之后自行解释。

## 二、构造可比的成对示教

**成对示教**是在可比任务条件下，记录有目标偏好与无该偏好的两组执行。其价值是减少无关差异，让下游判断行为变化是否与偏好有关。配对不是把两条长度接近的视频放在一起；需要明确哪些条件相同、哪些条件被有意改变。

LIBERO-PeRM 的流程先确定任务与布局，再生成无偏好和偏好条件下的子任务计划，调用启发式技能产生轨迹，并进行人工复核。部分用户背景偏好需要最小布局编辑以提供相应对象，任务语言也需覆盖两种条件。因此，数据中应保存布局编辑前后状态、被修改对象和修改原因，不能假设所有配对都具有逐像素相同的场景。

建议按以下步骤采集或生成：

1. 固定任务目标及验收条件，记录对象、布局、机器人和控制配置。
2. 保存偏好原文、类型、适用对象与上下文，标出可能的歧义及人工确认记录。
3. 创建无偏好对照和偏好条件；需要调整场景时保存编辑记录并检查原任务仍可完成。
4. 采集实际观测、动作、状态、接触和结果，保留失败及未满足偏好的样本。
5. 分别计算任务成功和偏好指标，将指标指向对应执行片段和标注规则版本。
6. 按源任务、布局及生成模板划分数据，再做窗口采样和指令改写，避免近重复泄漏。

时间对齐应把偏好适用区间与实际动作区间关联。例如运输阶段要求杯身竖直，不能只测最后放下时的姿态。跨长度配对可用“抓取—运输—放置”等阶段对应，而不能只按帧号对齐。空间对齐要保存偏好所指对象、区域和坐标系；路径避让标签必须使用与轨迹一致的单位和参考系。

## 三、最小数据字段

| 字段组 | 建议字段 | 用途 |
| --- | --- | --- |
| 任务 | `mission_id、goal_predicate、scene_version、robot_version` | 定义客观任务及相同实验条件 |
| 偏好表达 | `preference_id、raw_text、preference_type、context_text` | 保留原意与结构化条件 |
| 适用范围 | `target_entity、phase、valid_interval、reference_frame` | 说明要求作用于什么对象和动作段 |
| 条件解释 | `resolved_condition、interpretation_source、review_status` | 区分用户明确表达、模型推断和人工确认 |
| 配对来源 | `pair_group_id、condition、parent_layout、layout_edits、seed` | 追溯有偏好和无偏好对照 |
| 执行证据 | `episode_id、observations、applied_actions、object_states、events` | 重算动作与接触相关指标 |
| 独立标签 | `task_success、satisfaction_score、metric_version、evidence_span` | 避免把完成任务与满足偏好混为一谈 |
| 组合与冲突 | `preference_set、conflict_type、priority_rule、resolution_source` | 解释多个条件之间的关系 |
| 数据治理 | `source_type、annotation_version、reviewer、split` | 区分人工示教、程序生成及后续修订 |

若实际采集真实用户数据，可再补充授权范围、用户标识和偏好有效期；这属于扩展设计，不是 LIBERO-PeRM 已验证的长期用户建模能力。没有用户确认时，“根据上下文推断的偏好”应保留推断标签，不能伪装成已确认的个人档案。

## 四、指标、复核与组合测试

![评估将任务成功和偏好满足组成四格结果，再分别测试无偏好能力保持、跨任务布局迁移、偏好组合与冲突条件](/images/docs/personalized-preference-data-evaluation.svg)

最基本的报告应保留四种情况：任务成功且偏好满足、任务成功但偏好未满足、任务失败但局部行为符合偏好、两者都未满足。只在成功样本上统计偏好指标时，应同时公布成功样本数量和总体成功率，防止失败样本被筛除后得到过高满意度。也可以另外报告同时满足两项的比例，但不能用它替代原始两项指标。

连续指标与离散标签也要分开。论文的管线可从速度、距离、关键动作等计算原始满意度，再通过轨迹统计和人工检查映射为离散标签。工程数据应保留映射阈值、单位、参考分布和边界样本，避免后续阈值变化时无法复算。依赖视觉模型判断抓取方式时，要记录模型、提示词和图像证据，并抽样人工复核；生成模型认可自己的轨迹，不是独立质量保证。

**偏好组合**是同时要求多个条件，例如既缓慢运输又采用指定抓取方式；**偏好冲突**是这些条件彼此或与任务目标不能同时满足。采集组合数据时，可在同一任务布局下保留无偏好、仅 A、仅 B、A+B 四类条件，分别判断模型是否学会各项及其共同作用。冲突数据需要明确冲突由谁判定、采用什么优先级，以及是否需要澄清，不能把任意选中一项直接记为正确解决。

评估至少分为以下几条：

- **偏好响应**：给出或移除偏好时，行为是否按预期改变，任务成功率是否下降。
- **基础能力保持**：加入偏好数据后，无偏好任务是否仍能完成；混合训练的比例与任务组成须可复现。
- **跨任务与布局泛化**：相同偏好用于未见任务或布局时是否有效；训练与测试不得共享同一源轨迹的改写版本。
- **组合与冲突表现**：记录每项满意度、优先级和任务结果，分开报告可兼容组合与不可同时满足的条件。

## 五、使用边界与来源证据

LIBERO-PeRM 正文按“任务说明、布局和目标组成的 mission，再配一种偏好条件”计数；其 **312 个任务包含有偏好任务和无偏好对照**。五个套件中，ComprePref 复用已有任务并改写上下文提示，不为总数新增任务。不能将这一规模写成 312 种独立偏好，也不能把指令释义或随机初始位置重复计为新任务。

该基准只组合两项偏好，冲突套件不评估冲突检测或向用户澄清。它没有真机或长期用户研究，生成轨迹还可能受启发式技能库和生成管线偏差影响。上下文语言能够暗示偏好，不表示模型已经理解用户长期历史、非语言信号或开放变化的偏好。若数据集要支持这些目标，需要另行采集对应证据与测试集。

论文发现零样本个性化仍然困难；监督微调可让偏好变得可学，混合训练相对顺序适配更有利于保持无偏好能力，但可能削弱部分运动偏好的学习。这提示数据版本应同时保存偏好比例、类型分布和无偏好对照，并按类别报告结果，而不能只用一个平均成功率判断最佳混合方案。
