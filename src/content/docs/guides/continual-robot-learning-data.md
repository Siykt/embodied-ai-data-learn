机器人持续学习研究系统在任务不断到来时怎样吸收新经验，同时保持仍然有用的旧能力。对数据工作而言，关键对象不只是一批训练轨迹，还包括**任务流**：任务到来的先后顺序、每轮可访问的数据、实际更新的模型或技能、可用预算，以及更新前后的评测结果。

例如机械臂先学取杯子，再学开抽屉，最后学习处理滑落。只保存最终成功率，看不出开抽屉之后是否忘了取杯子，也看不出恢复能力来自新示教、更多重试还是新的控制程序。持续学习数据要让每一次能力变化都能追溯到当时可用的经验和更新。

## 一、先区分三种需要变化的对象

### 新能力与历史能力

**灾难性遗忘**是学习后续任务后，原本掌握的能力显著退化。冻结主模型不代表完全没有遗忘：负责引导、选择技能或检索经验的小模块也可能覆盖旧行为。[Dream to Remember（D2R）](https://arxiv.org/abs/2610.13816)以冻结世界模型生成旧任务的想象轨迹，约束持续更新的策略引导模块。这提示应分别记录哪些参数被冻结、哪些模块变化，以及每份回放来自真实执行还是世界模型。

**想象回放**是利用模型生成的状态和动作演化复习过去任务，属于派生训练材料。它需要世界模型版本、起始条件、动作来源和生成配置；预测看起来连贯，不等于真实环境也会这样变化。D2R 的原始摘要明确区分两种情况：世界模型足够忠实时可在想象中学新任务；否则仍在环境中学习新任务，只用世界模型复习旧任务。

### 稳定规律与过期事实

[What Should World Models Forget?](https://arxiv.org/abs/2610.03713)指出，环境变化后旧事实可能已经不正确，要求模型永远保持旧答案会误判正确更新。它提出按有效时间尺度区分保留对象，并分别报告不变量回归和修订延迟；这是评测口径提议，不能写成已证明某套持续学习方法全面优于基线。

数据中可将“对象仍存在”等协议定义的稳定性质，与“杯子当前在左边”“门现在打开”等实例状态分开。**修订延迟**是环境事实变化后，系统需要多久才能用新证据更新其记录或预测。标签应保存事实有效区间、观察到变化的时间和系统完成修订的时间。某个物体的摩擦、质量或工具状态也可能变化，不能把所有物理参数都标成永恒不变。

### 模型权重与外部经验

[SEAR](https://arxiv.org/abs/2610.18792)把控制代码、技能和记忆作为可积累经验，并通过重复尝试、预算和信息访问等对照判断是否真正学到东西。因此，数据快照应包含可执行技能版本、记忆条目和控制工具配置，而不只记录模型权重。某次成功若来自额外试验或读取了测试信息，应与可复用经验带来的收益分开。

## 二、把采集、接管和更新接成一条记录

采集每个新任务前，先固定任务说明、可访问的数据范围和更新前版本。新任务可以来自示教、自动探索、人工恢复或合成轨迹，但来源要显式标记；派生片段不得覆盖源 episode。旧任务是否允许重放、重放多少、选择依据是什么，都属于实验条件。

[EqC](https://arxiv.org/abs/2610.18790)利用动作细化过程中的能量一致性信号识别能力边界，持续违例触发专家接管，再汇总恢复轨迹进行后续更新。数据启示是同时保存触发信号、阈值与持续时长、请求接管时刻、专家实际取得控制的时刻，以及恢复后是否重新交还策略。能量一致性信号是该方法的模型内判断，不应直接标注成真实世界风险概率。其能力范围扩大也不能自动等同于所有旧任务已经保持。

[SARAM](https://arxiv.org/abs/2610.24804)在顺序任务中复用冻结的**适配器**，即附加于主模型、用于任务适应的小规模参数模块；只在部分层新增模块。它在每个 episode 起点依据观测和指令形成**任务签名**，选择任务更新并合并到骨干模型。数据应保留任务签名版本、选中任务、适配器组合和实际部署权重哈希，才能区分“学会了新任务”与“部署时选错了任务”。

建议每轮按以下顺序形成记录：

1. 保存更新前模型、技能、记忆、数据清单和评估协议快照。
2. 采集新任务经验，标出观测、实际动作、接管区间及任务结果。
3. 选择真实或想象回放，记录筛选规则、权重、数据版本和可访问时间。
4. 执行更新，保存变动模块、训练配置、预算与新增外部经验。
5. 在固定协议下回测仍有效的旧任务，并单独测新任务与事实修订。

时间对齐至少有两层：episode 内的观测—动作—接管时间，以及任务流上的数据获得—更新—评估顺序。后获得的数据不能出现在较早检查点的训练清单中。若硬件、坐标系或标定在任务流中变化，要保存变换与版本，避免把坐标错位误诊为遗忘。

## 三、最小数据字段

| 字段组 | 建议字段 | 用途 |
| --- | --- | --- |
| 任务流 | `stream_id、task_id、arrival_order、available_from、task_boundary` | 复现任务顺序及当时可用信息 |
| 经验来源 | `episode_id、source_type、source_policy、parent_episode、split` | 区分示教、探索、恢复和派生经验 |
| 接管 | `competence_signal、trigger_config、t_request、t_takeover、t_release` | 关联能力信号与实际控制来源 |
| 回放 | `replay_ids、selection_rule、weights、world_model_version、seed` | 复算回放选择与想象样本 |
| 更新快照 | `base_checkpoint、changed_modules、adapter_ids、skill_version、memory_version` | 说明到底更新了什么 |
| 部署选择 | `signature_version、selected_task、merged_checkpoint、t_select` | 分析任务识别与执行错误 |
| 有效事实 | `fact_id、valid_interval、change_evidence、revision_time` | 区分事实修订与能力遗忘 |
| 评测与预算 | `eval_protocol、checkpoint_id、eval_task、attempts、compute_cost` | 比较固定条件下的能力与资源 |

这些字段是建议的数据契约。某方法没有适配器时无需设置虚假的 `adapter_ids`；采用代码或记忆更新时，则必须保存那部分可执行与可检索状态。仅保留“模型版本号”无法恢复完整系统行为。

## 四、质量控制与分开评估

![持续学习评估把新任务适应、历史任务保持、实例事实修订和资源增长分为四项，并设置等预算重试、无历史经验与冻结版本对照](/images/docs/continual-robot-learning-data-evaluation.svg)

**数据准入检查。** 对恢复片段检查接管时间和动作来源，对想象片段检查生成器版本与起始观测，对历史记忆检查其事实是否仍有效。不能把模型自行写下的“成功”当作独立验收；保存可回放证据和独立判定结果。训练数据、历史经验库及正式测试任务要按源 episode、场景和任务实例隔离。

**每轮建立评测矩阵。** 行对应更新后的系统快照，列对应任务或固定测试切片。新任务列说明适应效果，旧任务列说明保持或退化；只有共同协议、有效标签与可比预算下的差异才有意义。可报告**后向迁移**，即学习后续任务后，先前任务性能相对其早期基准如何变化；负值反映退化，正值反映旧任务也受益。

**另测事实修订。** 对确已变化的场景状态，记录系统何时接受新证据、撤回旧判断。稳定性质的回归错误和过期事实的修订延迟分别报告，避免合成一个平均分后掩盖两类相反问题。评估应有独立变化真值及其有效时间，不能仅依赖模型自己的变化声明。

**控制尝试次数与成本。** 保持相同任务预算，比较长时间学习、等预算多次重试、禁用历史经验和使用冻结经验库。除成功率外报告示教数量、人工接管时间、模型调用、存储增长、episode 初始化延迟和控制频率。SARAM 的每步控制开销可与骨干相当，但任务起点仍需比较已存任务签名，磁盘状态也仍增长，不能简化为所有成本恒定。

## 五、数据集使用边界

固定世界模型生成的回放可能固化错误，数据集中应保留真实与想象来源，允许单独消融。历史事实需要按有效期修订，历史动作经验是否可复用则取决于任务和机器人版本；二者不能用同一条“保留越多越好”的规则处理。

SEAR 全文说明其真机实验从空技能库开始，测量的是硬件上的学习，并非仿真经验迁移到真机；墙钟预算匹配也不代表计算预算相等。SARAM 是有示教数据、明确任务顺序的终身模仿学习，不能据此宣称已支持任意时刻任务切换。D2R 的完全想象学习条件取决于世界模型保真度。新任务、旧能力、世界状态和成本必须各自保留证据，才能判断持续学习是否对目标部署有价值。
