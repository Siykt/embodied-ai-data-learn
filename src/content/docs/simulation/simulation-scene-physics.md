仿真轨迹的可信度从场景建模开始。一个能在画面中正常移动的机器人模型，不一定有正确的质量、惯量、关节限位或接触参数；这些差异会直接改变动作、接触事件和任务成功率。本页把“资产准备 → 模型转换 → 物理配置 → 校验与冻结”整理成可复用的数据生产流程。

![任务规格经资产、机器人模型和物理配置进入可复现仿真场景](/images/docs/simulation-assets-chain.svg)

## 1. 从数据目标反推场景规格

先写清将来要用数据回答什么问题，再决定建模精度。抓取数据需要物体几何、摩擦和接触；视觉定位数据更依赖相机、纹理、遮挡与尺度；移动机器人数据还要检查地面、轮胎或足端接触和可通行区域。

| 任务问题 | 必要输入 | 必要输出 | 重点误差 |
| --- | --- | --- | --- |
| 抓取与装配 | 物体尺寸、碰撞体、材质、夹爪参数 | 接触、物体位姿、夹爪状态、成功条件 | 穿透、摩擦、尺寸偏差 |
| 行走与移动 | 机器人质量分布、关节限制、地形 | 姿态、足端接触、速度、滑移事件 | 惯量、地面接触、控制延迟 |
| 视觉感知 | 网格、材质、灯光、相机 | RGB、深度、分割、标定 | 外观域差距、坐标和尺度 |

场景规格至少写明：机器人版本、任务目标、对象清单、尺寸单位、世界坐标约定、可变化参数及其范围、目标数据字段。随后给每个资产一个稳定 ID 和来源记录，避免同名文件在不同机器上指向不同内容。

## 2. 资产与格式：视觉几何不等于碰撞几何

机器人和物体通常同时有两套几何：**视觉几何**用于渲染，保留外观细节；**碰撞几何**用于接触计算，通常更简单。碰撞体过粗会把可抓位置“撑大”，过细或网格不规范则可能增加求解负担或产生不稳定接触。导出数据时，应分别记录两套几何的版本，并抽查它们的相对位置。

常见格式分工如下：

- **URDF** 描述机器人连杆、关节、惯量及视觉/碰撞几何，常用于机器人模型交换；材质、传感器和任务场景通常还要补配置。
- **MJCF** 是 MuJoCo 的模型格式，可定义机器人、场景、执行器、传感器和求解选项；网格与纹理等依赖仍需一同固定。
- **USD** 是 Isaac Sim 的场景与资产组织基础，可通过引用和变体组合大型场景；保存 USD 路径之外，还需固定引用资产及配置层。

格式转换不是逐字段无损复制。URDF 导入 MuJoCo 或 Isaac Sim 后，应逐项检查坐标轴、关节方向、限位、惯量、碰撞几何、执行器与传感器。不要把“成功加载”当作“动力学等价”。

## 3. 机器人本体与执行器

机器人模型要能回答四个问题：每个连杆在哪里、每个关节允许怎样运动、控制命令施加在哪里、传感器观察哪里。关节位置数组也不一定与关节数量一一对应，例如自由关节的姿态需要四元数。数据契约要保存关节名称、类型、顺序、单位和数组切片。

**惯性参数**描述质量如何分布，包括质量、质心与惯性张量；它们影响加速、制动和碰撞后的反应。**执行器模型**把控制命令转换为力或目标位置、速度，同时可能包含饱和、延迟和增益。若真实电机有通信延迟、死区或速度限制，仿真里理想化的直接力矩命令就会产生偏差。

![动作经过执行器、动力学与接触计算后形成状态和传感器读数](/images/docs/simulation-dynamics-loop.svg)

记录一次动作时，至少区分策略请求值、控制器处理后的命令、仿真执行器输入和下一状态。这样才能判断失败来自策略、动作映射还是模型动力学。

### 控制接口必须和数据语义一致

| 策略输出 | 进入物理引擎前常见处理 | 数据集必须额外记录 |
| --- | --- | --- |
| 关节位置目标 | PD 控制、限速、关节限位 | 目标位置、控制器增益、实际关节位置 |
| 关节速度目标 | 速度环、加速度或力矩限制 | 目标速度、饱和状态、控制周期 |
| 关节力矩 | 力矩裁剪、驱动器响应 | 请求与施加力矩、执行器延迟 |
| 末端位姿目标 | 逆运动学、轨迹插值、碰撞检查 | 目标坐标系、求解器版本、生成的关节命令 |

同一组数字在不同动作接口下含义完全不同。先固定控制接口，再做仿真数据集；若策略训练用末端增量、真实机器人执行用关节位置，应把中间转换器纳入数据血缘和验证。物理步长、控制周期和传感器采样周期的关系见[仿真传感器、渲染与时间对齐](/simulation/simulation-sensors-timing/)。

这里的 PD 控制指根据位置误差和速度误差计算控制量；逆运动学指由末端目标位姿求关节配置。两者都有多种实现和参数，因此数据集不能只写“位置控制”或“IK”，还应保存控制器版本及关键参数。

## 4. 接触、材质与求解设置

接触计算同时受碰撞几何、摩擦、接触柔顺性、时间步长和求解设置影响。物体看似相同，摩擦或质量不同就可能让抓取从成功变为滑落。MuJoCo 的接触参数与 Isaac Sim/PhysX 的材质和求解参数并非同名同义，跨引擎比较应使用共同的观测指标，而不能只复制数值。

至少检查以下现象：

- 静止物体是否自行滑动、弹跳或持续抖动；
- 抓取和落地时是否出现明显穿透、非物理冲量或过长的接触保持；
- 关节是否越限，动作饱和与安全限制是否真的生效；
- 改变物理步长后，关键任务结果是否突然翻转。

把求解器、积分器、物理步长、重力、接触参数与材质版本写进场景 manifest。随机化参数既要记录允许范围，也要在每个 episode 保存实际抽到的数值。

## 5. 建模校验与冻结

在大规模生成数据之前，先用一组小测试场景校验模型，而不是直接启动训练。建议至少覆盖自由下落、静止接触、单关节阶跃、夹爪闭合、典型任务成功与故意失败。每项都保存初态、动作序列和预期范围，以便模型或引擎升级后做回归。

![几何、运动学、动力学和真实对照四层校验](/images/docs/simulation-physics-validation.svg)

| 校验层 | 观察量 | 发现异常后的排查方向 |
| --- | --- | --- |
| 几何与坐标 | 尺寸、轴向、碰撞体与渲染体重合度 | 单位、坐标变换、导入选项 |
| 运动学 | 关节方向、限位、末端轨迹 | 关节树、轴向、零位、工具中心点 |
| 动力学 | 落体、接触、加速与制动曲线 | 质量、惯量、摩擦、执行器、步长 |
| 真实对照 | 同一动作下的位置、力和成功率 | 控制延迟、材质与传感器模型 |

“可复现”要限定范围。相同模型、初态、动作和引擎配置下，先比较本机重复运行；跨 GPU、引擎版本或 MuJoCo 与 MJX，再单独报告容差和任务结果，不要求逐位完全一致。

## 交付给下游的数据契约

```text
scene_manifest
  engine_name / engine_version / solver_config
  robot_id / model_file_hash / dependency_hashes
  visual_geometry / collision_geometry
  units / world_frame / joint_layout
  mass_inertia / actuator_config / joint_limits
  contact_materials / gravity / physics_timestep
  task_objects / initial_state_distribution
  conversion_tool_version / import_options
  validation_suite_version / validation_results
```

下游的[传感器与时间对齐](/simulation/simulation-sensors-timing/)要使用这些坐标、资产和物理时间设置；[任务与数据生成](/simulation/simulation-task-generation/)则把场景版本与每条 episode 绑定。MuJoCo 的字段实例见[MuJoCo 与具身数据](/simulation/mujoco-embodied-data/)，Isaac Lab 的场景组织见[Isaac Lab 与具身数据](/simulation/isaac-lab-embodied-data/)。
