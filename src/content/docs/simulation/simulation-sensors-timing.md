用手机拍视频、再用另一台设备录音时，两个文件都正常，并不代表它们能直接配在一起。声音只要早一点，画面里的人还没开口，我们就会先听到说话声。剪辑前必须先找到共同的时间。

机械臂把杯子放到托盘时，也会同时留下多路记录：相机拍下杯子，关节传感器记录手臂位置，接触传感器记录何时夹住、何时放下。把这些数据配错，训练样本就可能变成“先抓住，后伸手”。

读完本页，你能分清机器人实际看到了什么、仿真额外知道什么，并判断一张图像应该配哪一次动作。本页承接[场景与物理配置](/simulation/simulation-scene-physics/)，为接下来记录完整的放杯子任务做好准备。

## Why｜为什么仿真内部状态还要变成传感器观测？

机器人需要练习根据实际能收到的信息行动。仿真器知道杯子精确在哪里，即使机械臂挡住了杯子，真实机器人却可能只能从相机画面中寻找它。

如果训练时直接告诉机械臂杯子坐标，部署时却只给图像，它就还没有学过“从图像里找到杯子”这一步。因此，内部状态需要经过传感器模型，变成接近实际设备输入的记录。

因此要区分两件事：**状态**是仿真内部对世界的描述；**观测**是机器人通过传感器实际得到的输入。内部状态可以提供监督标签与评测依据，但只有部署时能获得的字段，才适合直接作为可部署策略的输入。

![仿真内部状态经传感器模型与渲染生成机器人观测，另一路提供监督和评测标签](/images/docs/simulation-sensor-stack.svg)

即使使用虚拟传感器，也要保存它的配置。相机装高一点，关节读数延迟一点，都会改变机器人“看到的情况”，从而改变后续动作和数据分布。

## What｜是什么数据从这些传感器中出来？

最容易理解的是相机图像，但一次放杯子还会留下手臂位置、夹爪接触等读数。它们从不同角度描述同一个过程：杯子在哪里，手臂到了哪里，杯子是否已经放到托盘上。

<span id="1-先定义每一路数据的身份"></span>

### 每一路记录都要能说明自己是谁

来自同一台相机的一串图像，可以看作一路数据流。桌面上方的相机和夹爪旁边的相机看到的角度不同，所以记录里要能分清每一帧来自哪一台。关节和接触读数也各有自己的来源说明。

例如一列关节角度，必须知道它属于哪几个关节、按什么顺序排列、用弧度还是角度。只有数值本身，下游无法可靠地回放动作或训练模型。

<span id="2-相机深度与分割"></span>

### 一台相机可以生成不同用途的图

同一个杯子可以有三种记录：RGB 图像保留颜色外观，深度图记录距离，分割图为像素标注对象身份。**语义分割**回答“这是杯子还是桌子”，**实例分割**进一步区分“这是左边还是右边的杯子”。两套编号的映射表不能混用。

把图像位置还原为空间位置，需要相机参数。**内参**描述像素与光线之间的关系；**外参**描述相机相对世界或机器人基座的位置和朝向。相机跟随机器人移动时，外参也在变，数据集开头的一组数值可能不够用。

这些图必须能相互对应。例如颜色图上杯子左侧被夹爪挡住，分割图就不能仍把被挡住的部分当作可见杯子。距离的定义、无效像素和对象编号等细节，放在附录中统一核对。

<span id="渲染标签的生成也需要规则"></span>

RGB、深度和分割可能由不同步骤生成。同一台虚拟相机输出的几张图，也要确认是在同一位置、同一时刻看到的同一个场景。

一个杯子“位于相机前方”，不等于它“在图像中可见”。前者可直接从状态算出，后者还要考虑视野和遮挡。用于目标检测的标签必须与图像证据一致，因此仍需要人工查看一批样本。

<span id="3-imu接触与射线传感器"></span>

### 运动和接触也需要自己的解释

杯子落到托盘上时，图像可以显示它的位置，接触读数则帮助判断它是否碰到了托盘。但“碰到了一下”和“稳定放好了”不同，不能只凭一个接触标记就宣布任务成功。

有些任务还使用 **IMU**，像手机里的运动传感器一样记录加速度与角速度；射线或激光类传感器则沿指定方向测量到物体的距离。放杯子任务是否需要它们，取决于机器人实际配了什么传感器和数据要用于什么。

传感器读数总有自己的解释规则。接触值是“这一刻接触”，还是“这一段时间曾经接触”；运动读数是否包含重力，都会影响判断。这些定义与噪声、延迟一起记录，具体项目见附录。

## Who｜谁产生观测，谁确认标签可信？

虚拟相机等传感器产生观测，仿真状态或标注程序提供标签，使用数据的人再检查两者能否对上。自动生成标签能省去大量手工标注，但仍需要抽样核对。

例如夹爪挡住杯子时，内部状态仍能给出完整杯子的位置，但图像里只露出半个杯身。标注规则的维护者要说清标签表示“完整物体”还是“可见部分”，数据使用者据此决定能否拿来训练目标检测。

传感器的配置者则确认相机安装、标定与噪声，策略的开发者确认真实机器人能拿到相同类型的输入。各自检查之后，观测和标签才有明确的用途。

<span id="5-标签来源与可观测性"></span>

## Where｜观测与标签分别送到哪里？

观测送给机器人作决定，标签用来教它学习或判断结果。例如机械臂根据相机图像寻找杯子，训练程序用杯子的分割图教它识别目标，评测程序则查看杯子是否最终放稳在托盘中。

这三个用途分别对应**策略输入**、**训练辅助标签**和**评估真值**。同一份记录可以服务多个用途，但使用时要说清正在扮演哪个角色。

![机器人可用的观测、训练辅助标签与评估真值分别保存，并记录各自来源](/images/docs/simulation-label-provenance.svg)

仿真中可直接读取、部署时却得不到的信息叫**特权状态**。它可以帮助训练和分析，但如果在评测可部署策略时混入输入，得到的成绩就不能代表真实部署条件。这就是为什么要明确字段用途。

相机装在哪里、怎样采样等信息保存在**传感器清单**中，标签也带上来源说明。它们和图像、读数一起交给[任务与数据生成](/simulation/simulation-task-generation/)，让以后使用数据的人能找到当时的设置。标定细节可继续看[相机内参数据要求](/guides/camera-intrinsics-data-requirements/)。

<span id="4-多时钟和采样对齐"></span>

## When｜什么时候这些观测才能与动作配成一条样本？

只有知道图像是在动作之前还是之后拍到的，才能把它们配成有意义的样本。机械臂准备张开夹爪时看到的杯子，与松手后落到托盘上的杯子，代表两个不同的时刻。

物理计算、动作更新和拍照也不总按同一节奏工作。举一个示意配置，数值并非实测：物理每 1 毫秒推进一次，动作每 20 毫秒更新，相机约每 33 毫秒拍一帧。因此第 10 张图和第 10 个动作未必同时发生，有时动作更新了，相机还没有新图。

![物理、控制、相机和 IMU 各自采样，通过共同的仿真时间轴建立对应关系](/images/docs/simulation-sensor-timeline.svg)

对一次“观察后行动”，至少要分清观测采样时间、动作发出时间、动作生效时间，以及下一观测的时间。动作生效后拍到的图像，不能回填成机器人做这个决定之前看到的输入。

通常用共同的仿真时间轴串起这些记录，同时保留各路数据原本的采样时间。需要估算中间读数或选择时间相近的帧时，要把方法和误差留下来。具体要求见附录与[多模态时空对齐数据](/guides/multimodal-spatiotemporal-alignment/)。

<span id="6-传感器质量控制"></span>

完成配对后，从保存的文件中回看一段“夹住、提起、放下”的过程。图像显示夹爪还没碰杯子时，接触读数有没有提前变化？松手后，杯子的位置和托盘接触是否对应？这样能直接发现数据是否在描述同一次动作。

最后对照真实设备。光照、材质和曝光改变的是图像外观，质量和摩擦改变的是运动，两类变化应分别记录。按距离、光照、速度、材质与接触条件比较噪声、反射、模糊和遮挡，才能说明这些数据适合哪些下游任务。

## 技术附录：传感器与时间字段

<details>
<summary>实施数据记录时需要的字段示例</summary>

为每路数据分配稳定的 `stream_id`，明确来源、单位、坐标系、采样时间的含义和允许用途。MuJoCo 可从模型和 `MjData` 读取状态与传感器数组，并通过 `Renderer` 生成图像；Isaac Sim 提供渲染与传感器能力，Isaac Lab 将其组织为环境观测。字段名同叫 `obs`，也要按实际任务配置解释。

```text
sensor_manifest
  stream_id / sensor_type / version
  mounting_pose / frame_convention / units
  camera_intrinsics / resolution / depth_definition
  sample_period / timestamp_definition
  noise_model / latency / label_mapping
transition_timing
  observation_time
  action_issue_time
  action_effective_time
  next_observation_time
label_metadata
  label_source / generator_version / coordinate_frame
  allowed_uses
```

相机外参若随时间变化，应作为时间序列保存。各类观测还需按用途补充：

- **视觉数据**：法线、分辨率、相机位姿与帧时间；深度沿光轴还是到相机中心的距离，单位、有效范围与无效像素编码；类别与实例 ID 映射、资产版本，以及透明、反射、背景和遮挡边界的处理规则。
- **关节与 IMU**：关节顺序、单位、滤波与延迟；IMU 安装方向、采样率、是否包含重力，以及偏置、噪声和延迟。偏置指读数长期偏离真实值的部分，真实设备还可能漂移或丢样。
- **接触与射线**：接触表示碰撞事件、接触力还是冲量，阈值与聚合时间是什么；冲量是一段时间内力的累计作用。射线还需记录方向、量程、未命中编码与扫描时间。

用插值估算中间值，或用最近样本配对时，保存方法、允许误差与实际最大误差。频率从运行记录核对，不由目标帧率推断。合并真实采集时，提供仿真时钟与设备时钟的映射或同步事件；时间戳数值接近不证明同时发生。

回读时检查时间是否倒退、帧是否重复或缺失、图像是否为空、深度无效值与实例编号是否正确，再与引擎状态对照。机器人或相机重置后复查坐标与外参。物体材质、可见性和成功标签也必须注明来源。
