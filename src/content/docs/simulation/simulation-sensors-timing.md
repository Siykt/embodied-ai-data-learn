物理引擎中的物体位置是内部状态，机器人真正能使用的则是相机、IMU、关节编码器等传感器观测。仿真数据集需要把两者分开：内部状态可提供监督标签，但不能悄悄混进部署时不可获得的策略输入。本页承接[场景与物理配置](/simulation/simulation-scene-physics/)，整理“状态 → 传感器模型 → 图像或数值观测 → 对齐与标注”。

![仿真状态经过传感器与渲染模型生成观测和标签](/images/docs/simulation-sensor-stack.svg)

## 1. 先定义每一路数据的身份

每条观测流应有唯一的 `stream_id`，并明确来源、单位、坐标系、时间戳语义和可用性。策略可以读取的 observation、训练时使用的特权状态、评估用的仿真真值应放在不同字段。

| 数据流 | 例子 | 需要保存的解释信息 |
| --- | --- | --- |
| 视觉 | RGB、深度、法线、语义/实例分割 | 相机模型、内外参、分辨率、深度编码、类别 ID |
| 本体感觉 | 关节位置/速度、执行器状态 | 关节顺序、单位、采样周期、滤波与延迟 |
| 运动与接触 | IMU、接触、力/力矩、射线距离 | 传感器安装位姿、量程、噪声、事件阈值 |
| 仿真真值 | 物体位姿、材质、可见性、成功条件 | 引擎状态或渲染来源、生成规则、使用权限 |

MuJoCo 可从模型与 `MjData` 读取状态和传感器数组，并通过 `Renderer` 生成图像。Isaac Sim 提供更丰富的渲染与传感器能力，Isaac Lab 把它们组织进环境观测。两者的数据字段必须按具体任务配置解释，不能把同名 `obs` 数组直接视为可互换。

## 2. 相机、深度与分割

**相机内参**描述像素与光线的关系，**外参**描述相机相对世界或机器人基座的位置和朝向。即使图像来自仿真，也要保存内外参、图像宽高、相机坐标约定和每帧时间。相机跟随机器人或重置时，外参可能随时间变化；只在数据集头部保存一组固定外参可能不够。

深度图要注明测量定义与单位，例如沿光轴的距离或到相机中心的距离，并说明背景、无效像素、裁剪范围如何编码。分割图要提供类别与实例 ID 映射、资产版本、遮挡规则；图像中的一个整数 ID 没有映射表就无法成为稳定标签。

视觉几何、材质、光照、曝光和渲染器版本会改变 RGB 分布，却不一定改变物理轨迹。因此评估视觉模型时，要分开记录“外观随机化”和“动力学随机化”，还要核对图像与真实相机在噪声、反射、运动模糊和遮挡上的差异。

### 渲染标签的生成也需要规则

一张 RGB 图、一张深度图和一张分割图通常来自同一虚拟相机，但它们可能由不同渲染通道或后处理步骤产生。记录器要核对三者的分辨率、相机位姿和帧时间，说明透明物体、反射表面、遮挡边界及背景像素如何处理。语义分割表示类别，实例分割区分同类的不同对象；两种 ID 映射不能混用。

从内部状态计算的“物体在相机前方”与图像中“物体可见”也不同：前者可能忽略遮挡和视野边界。若数据用于目标检测或操作可见性评估，标签规则应与图像证据一致，并对一批样本做人工可视化抽检。

## 3. IMU、接触与射线传感器

IMU 通常提供加速度和角速度。将理想仿真状态转成 IMU 数据时，要约定重力是否已包含、传感器安装坐标、采样率、偏置、噪声和延迟。真实 IMU 的零偏漂移与丢样会改变下游定位效果，不能只给干净的理想数值。

接触数据要说明记录的是接触布尔值、接触点、法向力、冲量还是一段时间内的聚合事件。不同引擎对接触求解、阈值和时间步的处理不同；比较时应先把语义统一，例如“足端在该控制周期内曾接触地面”。射线或激光数据还要记录射线方向、有效量程、未命中值和扫描时间。

## 4. 多时钟和采样对齐

物理、控制与传感器不一定同频。物理引擎可能每个小步推进一次，策略每若干个物理步才更新动作，相机又以较低帧率输出。数组下标相同并不证明同时；对快速操作或高速运动，几毫秒错位都可能把接触前后的图像和动作配反。

例如一个项目可以用 1 ms 物理步、20 ms 控制周期和约 33 ms 相机周期。此时一次动作更新之间有多个物理状态，而两次控制更新之间未必都有新图像。数字只是示例；真实配置应从运行记录读取，不能从目标帧率推断实际落盘帧率。

![物理、控制、相机与 IMU 在不同时间节奏下对齐](/images/docs/simulation-sensor-timeline.svg)

推荐统一使用仿真时间轴，同时为各流保留自身的采样时间。对一次控制转移，明确记录 `observation_time`、`action_issue_time`、`action_effective_time`、`next_observation_time`。视觉帧若晚于动作生效，不能作为该动作的前置观测。插值或最近邻配对也要保存方法、容差与最大误差。

当仿真与真实采集数据合并时，还要区分仿真时钟和真实设备时钟。若要对齐真实相机、机器人控制器与仿真回放，应提供时钟映射或同步事件，而非直接比较数值时间戳。

## 5. 标签来源与可观测性

仿真内部的物体位姿通常是精确标签，但真实机器人可能只能从 RGB-D 图像估计它。若训练时直接把物体真值放进策略 observation，评估时又换成真实相机，就发生了可观测性不一致。建议把数据分成三层：

1. **可部署观测**：目标设备在实际运行时能得到的 RGB、深度、关节和触觉等。
2. **训练辅助标签**：仿真物体位姿、语义分割、接触状态等，可用于监督或质量检查。
3. **评估真值**：成功条件、目标位姿、碰撞事件等，只在评测或误差分析使用。

![可部署观测、训练辅助标签和评估真值的来源关系](/images/docs/simulation-label-provenance.svg)

每条标签应带 `label_source`、生成版本和坐标系。由渲染得到的分割、从状态计算的相对位姿、人工或模型后处理的标注，来源不同；混合使用前要检查规则和误差。

## 6. 传感器质量控制

- **标定**：检查内外参、坐标系方向、单位、相机跟随或重置后的位姿变化。
- **时间**：检测重复/倒退时间戳、丢帧、超出容差的多流配对和动作前后顺序错误。
- **图像**：检查空帧、裁剪、深度无效值、实例 ID 跳变与分辨率变化。
- **物理观测**：对照引擎状态检查 IMU 方向、关节读数、接触阈值和事件持续时间。
- **真实差异**：按材质、距离、光照、运动速度和接触条件分桶比较仿真与真实分布。

交付给[任务与数据生成](/simulation/simulation-task-generation/)的传感器 manifest 至少应包含：`stream_id`、传感器类型、安装位姿、内参、采样周期、时间戳定义、单位、噪声模型、标签映射和版本。视觉相机的详细要求另见[相机内参数据要求](/guides/camera-intrinsics-data-requirements/)与[多模态时空对齐数据](/guides/multimodal-spatiotemporal-alignment/)。
