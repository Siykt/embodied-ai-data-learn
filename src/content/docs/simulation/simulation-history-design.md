具身仿真不是“做一个会动的三维画面”。它是一套可重复的实验系统：先描述机器人和世界，计算动作造成的变化，再生成机器人能看到的观测，最后把交互过程保存成可训练、可评估的数据。理解它的发展史，关键不是背软件发布日期，而是看每一阶段**遇到了什么问题，因此新增了哪层设计**。

这篇入门页用一个主线回答三个问题：仿真系统由哪些层组成？MuJoCo、Isaac Sim、Isaac Lab 为什么分别出现？今天怎样判断一套仿真数据是否真的可用？文中的年份是代表性论文或项目节点，不表示某项能力在那一年首次出现，也不表示旧技术已被淘汰。

## 一、先建立整体图景：五层系统

![具身仿真从场景与物理到任务环境、记录器和评测的五层结构](/images/docs/simulation-history-stack.svg)

| 层 | 解决的问题 | 典型输入与输出 | 初学者容易混淆的地方 |
| --- | --- | --- | --- |
| 场景与资产 | 世界里有什么、机器人长什么样 | 模型、材质、坐标 → 可加载场景 | 看起来像真的，不代表碰撞体和质量正确 |
| 物理引擎与传感器 | 动作之后会怎样、机器人能观测什么 | 状态、动作 → 下一状态、接触、图像/数值观测 | 引擎内部真值不等于真实机器人可见信息 |
| 任务环境 | 从哪里开始、怎样行动、何时算成功 | 初态、观测、动作、目标 → 一次任务过程 | 奖励函数不等于客观成功条件 |
| 数据记录器 | 怎样保存多次交互并解释每个字段 | 时间流、状态、动作、事件 → episode 数据集 | 录屏不等于可回放的训练数据 |
| 评测与真实对照 | 数据和策略是否可信、能否迁移 | 数据集、策略、真实样本 → 指标与失败分析 | 仿真成功率不等于真机成功率 |

**物理引擎**主要计算运动、约束和接触；**仿真平台**还会组织场景、资产、渲染和传感器；**任务框架**再定义重置、观测、动作、奖励与结束规则；**数据集**是按明确 schema 导出的结果。MuJoCo 更接近引擎及模型接口，Isaac Sim 是更广的仿真平台，Isaac Lab 建立在 Isaac Sim 上组织机器人学习任务。它们处在不同层次，不能只按“哪个更新”选择。

遇到不熟悉的名词，可配合[具身智能数据术语表](/reference/terms/)阅读；本页先关注各层的职责和相互关系。

## 二、发展路径：每一步补上前一步缺少的能力

![从机器人系统集成到接触控制、标准任务、真实迁移、离线数据和并行多传感器的代表性发展节点](/images/docs/simulation-history-timeline.svg)

| 代表时期与资料节点 | 当时突出的需求 | 新增的设计能力 | 对具身数据的影响 |
| --- | --- | --- | --- |
| 2000 年代：2004 年 [Gazebo 论文](https://doi.org/10.1109/IROS.2004.1389727) | 在虚拟世界里联调机器人、传感器与多个任务对象 | 场景、物理、传感器和机器人软件协同 | 可以记录接近机器人系统接口的试验过程 |
| 2012 年：[MuJoCo 论文](https://doi.org/10.1109/IROS.2012.6386109) | 接触丰富的控制任务需要高效、可配置的动力学 | 专注模型、执行器、接触与求解的物理引擎 | 高频状态、动作和接触轨迹更容易批量实验 |
| 2016—2018 年：[OpenAI Gym](https://arxiv.org/abs/1606.01540)、[DeepMind Control Suite](https://arxiv.org/abs/1801.00690) | 不同算法需要统一任务入口与可比较结果 | `reset`、`step`、观测、动作、奖励等任务接口和基准 | rollout 更易组织，但 benchmark 分数依赖任务定义 |
| 2017 年后：[视觉领域随机化](https://arxiv.org/abs/1703.06907)、[动力学随机化](https://arxiv.org/abs/1710.06537) | 仿真视觉和动力学与真实设备存在系统差异 | 在受控范围内改变外观、场景或动力学参数并做真实对照 | 样本覆盖变广，同时必须记录采样范围与实际取值 |
| 2020 年：[D4RL](https://arxiv.org/abs/2004.07219) 等离线基准 | 训练与比较不应总依赖重新在线采样 | 可复用的轨迹数据集与离线评测协议 | 终止语义、数据来源、质量和划分开始成为核心问题 |
| 2021 年：[Isaac Gym](https://arxiv.org/abs/2108.10470) | 机器人学习需要大量并行交互 | GPU 上的并行物理与训练流水线 | 轨迹产量提高，渲染和写盘仍可能成为瓶颈 |
| 2020 年代：[Isaac Sim](https://docs.isaacsim.omniverse.nvidia.com/latest/index.html) 与 [Isaac Lab](https://isaac-sim.github.io/IsaacLab/main/index.html) 工作流 | 需要组合复杂资产、视觉传感器、并行任务和示教 | USD 场景、传感器与任务配置的集成 | 图像、深度、分割、动作和标签能进入统一生产流程 |

这条时间线不是一条“前者被后者取代”的产品线。Gazebo 的机器人系统联调、MuJoCo 的接触控制实验、Isaac Sim/Lab 的资产和多传感器工作流，都仍服务于不同需求；同一项目也可能把多个工具放进一条数据链路。

### 1. 从“机器人能在虚拟世界运行”到“接触动作可研究”

早期机器人仿真的核心价值，是让机器人程序、场景和传感器先在虚拟环境里协同运行。它降低了硬件实验成本，也便于复现某个场景。但当研究问题转向抓取、行走和复杂接触时，模型参数、执行器和接触求解对结果的影响会更突出。MuJoCo 代表了这条强调控制和接触动力学的路线。

对数据生产者而言，这一阶段形成了第一条原则：**场景文件和物理参数也是数据的一部分**。只保存动作数组，不保存机器人模型、关节顺序、摩擦与步长，就无法解释轨迹为何成功或失败。

### 2. 从“能运行”到“能比较算法”

标准任务接口让研究者用相似的方式重置环境、下发动作、读取观测和统计回报。`reset` 把任务放回一个初始状态，`step` 接收动作并返回下一步结果；从开始到结束的一次完整尝试叫 episode，策略在其中实际执行形成的过程记录常叫 rollout。接口统一推动了强化学习基准的使用，但不保证任务语义统一：同样叫 `done`，可能是成功、失败，也可能只是时间用完。

因此数据集需要比训练接口多保存一步：明确的任务版本、成功规则、自然终止、超时和失败原因。否则算法分数看起来可比，底层数据却未必能对齐。

### 3. 从“仿真分数”到“真实机器人是否有效”

相机噪声、物体材质、执行器延迟和摩擦都会造成仿真到真实的差距。领域随机化尝试让策略见到更宽的变化范围；系统辨识则用真实测量收窄关键参数的不确定性。两者都需要真实样本作为证据，不能只凭“把参数随机得更广”判断迁移效果。

这一阶段把仿真从单纯的训练场变成**可校准的数据生成器**：既要记录随机化范围，也要记录每次 episode 实际抽到的参数，并用未参与校准的真机任务验证结果。

### 4. 从“在线交互”到“可复用的数据资产”

离线强化学习和模仿学习让已有轨迹可以反复用于训练、比较与复盘。数据生产不再只关心每秒能跑多少步，还要关心轨迹来源、动作时间、观测是否完整、失败样本是否保留、训练与评测是否泄漏。字段、单位、时间语义和版本的约定通常写成 schema（数据模式）。D4RL 是这一转向的代表性基准之一；它是历史节点，不是所有具身数据都应采用的唯一格式。

大规模并行仿真进一步降低了采样成本，但也放大了记录问题：多个环境异步 reset、相机帧率低于控制频率、写盘跟不上物理步进时，轨迹很容易混段或丢帧。数据质量不会随产量自动提高。

### 5. 从“状态轨迹”到“多传感器数据闭环”

当前许多任务同时需要 RGB、深度、分割、IMU、接触、动作和任务标签。资产、渲染、物理、任务环境和数据导出需要协同；Isaac Sim 与 Isaac Lab 展示了这种集成路线。MuJoCo 也能输出图像和传感器数据，但项目必须依据自身任务权衡模型控制、视觉需求、规模、硬件和数据格式。

今天的目标不只是“跑通仿真”，而是让每个数据集可以回答：场景从哪里来、动作如何生效、每个标签由谁生成、哪些样本通过质检、策略在哪些条件下失效、真机差距有多大。

## 三、为什么技术栈会长成现在这样

![仿真发展中的需求、设计响应和最终数据产物之间的因果关系](/images/docs/simulation-history-design-drivers.svg)

| 需求增加 | 仅靠原有层会遇到的问题 | 因而加入的设计 | 必须留下的证据 |
| --- | --- | --- | --- |
| 抓取、行走等接触任务 | 视觉上碰到了，物理结果却不稳定 | 碰撞几何、惯量、摩擦、执行器和求解配置 | 模型与参数版本、接触事件 |
| 用相机训练策略 | 引擎内部状态比真实机器人“知道得太多” | 渲染、标定、噪声模型与观测/真值隔离 | 图像时间、相机参数、标签来源 |
| 比较多个算法 | 不同实验的任务和结束规则不一致 | 标准环境接口与冻结评测协议 | 任务版本、尝试数、成功/超时定义 |
| 扩大数据规模 | 单环境采样慢，人工示教成本高 | 并行环境、随机化、示教扩增 | 种子、变体、原始示教血缘、有效产量 |
| 部署到真实设备 | 仿真参数和真实世界有差距 | 系统辨识、域随机化、真机留出评测 | 校准集、留出集、域差距报告 |

由此可以看出，技术栈并不是为了让软件“功能越来越多”而堆叠。每增加一层，都是为了让某类实验变得可执行、可比较或可验证；同时也增加新的配置和数据质量责任。

## 四、用一个抓取杯子的任务串起全部设计

设定目标：机器人从桌面拿起杯子并保持两秒。下面每一步都回答“如果省略它，下游会误解什么”。

![抓取杯子案例从任务定义、建模、观测、采样、记录到真机验证](/images/docs/simulation-history-grasp-example.svg)

1. **定义任务**：杯子离桌面达到规定高度并稳定保持两秒才算成功；碰撞、滑落、超时分别记录。否则奖励高不一定代表真的抓住。
2. **准备资产**：保存机器人、杯子和桌子的尺寸、视觉/碰撞几何、质量及版本。否则“抓取成功”可能只是碰撞体比实物更宽。
3. **配置物理与控制**：固定摩擦、夹爪力、关节控制方式、物理步长与控制周期。否则同一动作数组在不同配置下会造成不同轨迹。
4. **配置观测**：相机图像、关节状态与接触信息按各自时间戳记录；杯子精确位姿作为辅助标签，不直接塞进只看相机的策略输入。
5. **生成变体**：改变杯子位置、尺寸、材质和光照，但拒绝不可达或初始穿透的场景；为每次采样保存实际参数。
6. **记录与质检**：每次尝试分配独立 episode ID，保存请求动作、实际命令、图像、状态、成功与失败原因，并检查丢帧、时间顺序和异常接触。
7. **评估与真机对照**：按未见杯子或材质隔离测试，统计成功率与滑落率；用少量真实抓取检查延迟和摩擦差距，再决定是否修改模型或采集更多真实数据。

这样得到的不是“许多仿真视频”，而是一批能追溯到资产、物理参数、策略和任务结果的交互数据。具体字段与操作步骤分别见[场景与物理配置](/simulation/simulation-scene-physics/)、[传感器与时间对齐](/simulation/simulation-sensors-timing/)、[任务与数据生成](/simulation/simulation-task-generation/)和[验证与真实迁移](/simulation/simulation-validation-sim2real/)。

## 五、几组持续存在的设计权衡

| 权衡 | 只追求一端会怎样 | 更可靠的判断方法 |
| --- | --- | --- |
| 物理精度与采样速度 | 极简模型可能漏掉接触失败；极复杂模型可能让有效数据产量过低 | 先列出任务敏感的物理量，再测包含渲染与落盘的有效 episode 产量 |
| 高保真图像与可迁移观测 | 图像漂亮仍可能缺少真实噪声、遮挡或正确标定 | 以目标真实相机的数据分布做对照，分开评价外观和动力学 |
| 干净的仿真真值与可部署信息 | 用精确物体位姿训练的策略可能依赖真机无法直接获得的信息 | 将策略观测、辅助标签和评估真值分开，并检查信息泄漏 |
| 标准基准与真实任务多样性 | 固定场景便于比较，却可能让算法记住少量布局 | 保留可复现基准，同时按未见资产、场景和真实任务做留出评测 |

因此工具选型没有单一“最先进”答案。应从下游数据用途出发，先定必须准确的部分，再决定在哪些地方用并行、随机化或更丰富的传感器换取覆盖。

## 六、今天如何理解 MuJoCo 与 Isaac Lab

| 如果首先要解决…… | 可以先研究…… | 仍需自行明确…… |
| --- | --- | --- |
| 接触、关节控制和高频低维轨迹 | [MuJoCo / MJCF / MJX](/simulation/mujoco-embodied-data/) | 任务环境、相机与记录格式、原生引擎和 MJX 的差异 |
| 大型 USD 场景、多相机、多传感器和并行任务 | [Isaac Sim / Isaac Lab](/simulation/isaac-lab-embodied-data/) | Lab/Sim 版本匹配、资产依赖、传感器时序与导出契约 |
| 与真实机器人软件和 ROS 传感器链路联调 | [Gazebo 等系统仿真路线](/simulation/simulators-embodied-data/) | 插件与传感器语义、真实设备时间对齐 |

这是按**数据目标**给出的起点，不是物理精度或速度排名。同一任务要比较两套仿真器时，先统一模型、动作表示、初态、控制周期、传感器和成功条件，再测真实硬件上的差异。

表中的 MJCF 是 MuJoCo 的模型与场景描述格式，MJX 是基于 JAX 的批量仿真路径；USD 是 Isaac Sim 用来组织场景与资产的格式体系。这些格式与运行方式决定怎样复现场景，却不能替代 episode 记录和评测规则。

## 七、入门者的学习顺序

| 顺序 | 先回答的问题 | 做出的最小产物 |
| --- | --- | --- |
| 1. 看懂一份模型 | 机器人有哪些关节？视觉和碰撞几何是否一致？ | 资产清单、单位与关节表 |
| 2. 跑通一个固定动作 | 一个动作何时生效、经过几个物理步？ | 带时间戳的状态和动作轨迹 |
| 3. 加入一个传感器 | 图像或 IMU 对应哪个坐标系、哪个时刻？ | 一条带标定与时间的观测流 |
| 4. 定义一个明确任务 | 成功、失败和超时如何判定？ | 可重复的 episode 与结束原因 |
| 5. 生成少量变体 | 随机化扩大了什么范围，有无无效任务？ | 任务变体表、种子和质量报告 |
| 6. 做一次真实对照 | 哪些差异来自观测、控制或接触？ | 仿真与真实的配对结果和失败分析 |

完成这六步后，再追求并行规模和复杂视觉。对入门者而言，一条字段解释清楚、能复现且有真实对照的轨迹，比大量无法解释的 episode 更有学习价值。
