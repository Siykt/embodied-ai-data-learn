仿真系统能够稳定产出轨迹，不代表轨迹适合训练或评测。验证需要逐层回答：场景物理是否合理、观测和动作是否对齐、数据是否覆盖目标任务、策略指标是否可信、真实设备上能否复现关键行为。本页承接[任务与数据生成](/simulation/simulation-task-generation/)，给出从单条 episode 到数据集发布的检查流程。

![仿真验证从文件完整性逐层进入物理、任务和真实世界对照](/images/docs/simulation-validation-ladder.svg)

## 1. 四层验证分别回答什么

| 层次 | 核心问题 | 典型证据 | 不通过时的动作 |
| --- | --- | --- | --- |
| 结构完整性 | 文件能否读取，字段与时间轴是否一致 | schema 校验、回读、缺失率、时间单调性 | 修复记录器或拒收样本 |
| 物理与传感器有效性 | 运动、接触、图像是否符合配置 | 穿透、抖动、关节限位、标定重投影 | 调整模型、求解与传感器配置 |
| 任务与分布有效性 | 标签、终止、覆盖和划分是否可信 | 成功条件复算、失败簇、任务变体覆盖 | 修正规则或补采数据 |
| 真实迁移有效性 | 仿真表现能否解释真机结果 | 配对任务、轨迹与失败模式差异 | 校准仿真或限定使用边界 |

每层都应输出可追溯的结论：通过、拒绝或需人工复核，以及规则版本、证据和受影响的 episode ID。不能用一次“平均成功率高”覆盖前面几层质量问题。

## 2. 单条 episode 和批量数据的检查

单条 episode 先检查：初态在允许范围内，物体没有初始穿透；时间戳不倒退；动作生效时间晚于相应观测；传感器流有明确缺失编码；结束原因与成功标记一致。接触任务还应检查抓取、滑移、释放等关键事件前后的图像、力和位姿是否互相解释。

批量数据再检查：任务、场景、资产、初态、随机参数和控制来源的覆盖；成功与失败比例；异常值和重复轨迹；各类质量拒绝原因。样本数量大不等于有效覆盖广，报告中要按任务变体与困难条件分桶，而不是只给总数。

质量阈值要对应下游用途。例如模仿学习可能要求动作与图像完整、成功条件可靠；离线强化学习可保留明确标注的失败轨迹；安全评测则需要保留近失、碰撞和停止事件。不要把所有失败样本一概删除。

## 3. 评测集隔离与可比性

训练集、验证集和留出评测集应按 episode、任务变体、资产族或场景划分。若同一场景的不同帧被随机分入训练和测试，模型可能只记住外观；若同一条示教的扩增轨迹横跨两边，指标也会偏高。划分规则、成员清单和数据集版本必须冻结。

![按场景、资产和示教血缘隔离训练、验证与留出评测](/images/docs/simulation-split-isolation.svg)

报告策略结果时，至少附上任务定义、环境和资产版本、尝试次数、成功率、失败原因、超时率、碰撞率和人工接管率。对成功率等指标给出按 episode 或任务分桶的置信区间，避免把同一轨迹的连续帧当成独立试验。比较两个策略时，优先使用相同的初态和任务变体做配对评估。

不同仿真器之间的成功率不能直接相减后就称为“物理引擎差异”。先统一机器人模型、任务目标、动作表示、控制周期、相机参数、终止条件和随机化分布，再比较轨迹、接触事件和成功率。无法统一的部分要明确写在报告里。

## 4. 复现和回归

至少保留一个小型固定用例集：自由下落、单关节响应、典型接触、成功任务和失败任务。引擎、模型或传感器代码升级后，重跑并比较状态轨迹、接触事件、图像尺寸/标签映射和终止原因。数值完全一致可能受硬件与并行执行影响，因此预先定义容差及任务级不变量。

MuJoCo 原生计算与 MJX 之间、Isaac Lab 不同版本之间，都要把“可运行”和“结果等价”分开验证。复现报告至少包含引擎版本、代码提交、资产哈希、随机种子、硬件、并行规模和渲染设置。不同版本产生的数据应保留来源，不应静默合并为一个同质数据集。

## 5. 从真实样本校准，再用真机验收

真实数据可以用来估计尺寸、质量、摩擦、执行器延迟、相机噪声和任务初态分布；这一步可称为系统辨识或参数校准。校准集与最终真机测试集应分开，否则仿真可能只对已见条件拟合得好。域随机化用于覆盖不确定范围，但不能替代实测证据。

![真实测量校准仿真，仿真生成与评估再回到真机验证的闭环](/images/docs/simulation-sim2real-loop.svg)

建议在同一任务变体上并列查看：视觉差异、接触与滑移、动作延迟、轨迹偏差、成功率和失败原因。若仿真成功率远高于真机，应定位是观测域差距、动作接口、物理接触还是任务分布造成，而不只是继续增加仿真轨迹数量。

| 观察到的差异 | 优先检查的证据 | 可进行的配对实验 |
| --- | --- | --- |
| 视觉策略在真机识别失败 | 相机内外参、曝光、反射、遮挡与分割边界 | 固定动作，只替换仿真/真实图像或相机参数 |
| 接触后滑落或装配卡住 | 摩擦、碰撞几何、质量、夹爪力与接触事件 | 固定初态和动作，比较接触轨迹及力 |
| 真机动作迟到或振荡 | 控制频率、网络/执行器延迟、限幅与增益 | 固定观测回放，比较请求与实际动作时序 |
| 某些物体或布局特别差 | 资产尺寸、任务变体和训练/评估覆盖 | 按物体与布局分桶，检查是否超出生成范围 |

这种配对实验一次只改变一类条件，便于把“模型能力不足”和“数据或仿真假设错误”分开。每次修正后重新冻结配置，并在未用于校准的真实任务上复测。

真机测试有成本和风险，可先选择代表性、边界性和仿真不确定性高的任务做分阶段验证。发布数据集时，写清哪些结论只在仿真内成立，哪些已由真实设备验证。

## 6. 数据集发布与模型使用边界

发布包建议同时包含数据、schema、任务规格、资产与引擎版本、生成配置、split、质量报告、许可证及已知偏差。每个训练或评估结果应能回链到数据集版本、环境版本和策略版本。若图像或标签需要后处理，保存处理代码版本与父数据 ID。

一种实用的发布摘要：

```text
release
  dataset_id / schema_version / license
  task_manifest / scene_manifest / sensor_manifest
  engine_versions / code_commits / asset_hashes
  episode_count / duration / task_coverage
  split_manifest / quality_rule_version / rejection_summary
  benchmark_protocol / confidence_intervals
  real_world_calibration_set / real_world_holdout_result
  known_domain_gaps / approved_downstream_uses
```

如果数据用于策略训练、感知监督或安全评测，分别写明可使用的字段和限制。仿真真值可以帮助训练和分析，但评测时应避免向策略泄漏现实部署不可获得的信息。更一般的数据质量方法见[具身数据质量与基准评估](/guides/embodied-evaluation-data-quality/)，合成数据与真实迁移的专题见[合成数据与仿真到真实迁移](/guides/synthetic-data-sim-to-real/)。
