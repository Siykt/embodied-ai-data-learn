description: 从模拟考试与正式考试理解仿真验证，说明要检查什么、怎样隔离评测数据，以及何时能支持真实设备上的结论。
---

模拟考试拿到高分，通常是好消息，但还要看试卷是否太熟、评分是否正确，以及题型是否覆盖正式考试。如果练习题和考试题只是换了顺序，成绩就很难说明遇到新问题时的能力。

让机械臂把杯子放到托盘上的仿真训练，也需要这样验收。画面中杯子到了托盘上，还要看它有没有穿进托盘、夹爪是否真正松开，以及记录中的“成功”是否和画面一致。

读完本页，你能沿着一条放杯子记录检查问题，判断成功率能说明什么，以及何时还需要真实机械臂验证。本页承接[任务与数据生成](/simulation/simulation-task-generation/)，为已经采出的数据划清使用范围。

## Why｜为什么仿真成功率高还需要继续验证？

成功率只说明策略在当前场景和判定规则下的表现，还不能说明数据正确或真机也能成功。例如杯子刚碰到托盘就被判定成功，即使随后倒下，统计结果也可能很好看。

也可能是评测时直接告诉了机器人杯子坐标，真实使用时它却只能看图像。验证就是把这些条件逐项查清：评分是否符合任务目标，策略是否用了应该得到的信息，保存的数据能否证明结果。

![验证从文件完整性开始，依次检查物理与传感器、任务与分布，最后与真实世界对照](/images/docs/simulation-validation-ladder.svg)

数据用于模仿学习时，动作与图像的完整性通常很关键；离线强化学习可以使用明确标注的失败轨迹；安全评测还需要碰撞、停止和险些失败的记录。验证要对应用途，不能把所有失败样本一概删除。

<span id="1-四层验证分别回答什么"></span>

## What｜是什么证据支持一份仿真数据可用？

先证明过程被完整保存，再证明记录合理、任务判断正确，最后与真实设备对照。这四层分别回答不同问题，可以沿着同一轮放杯子的记录往下看。

### 第一层：保存下来的数据能否读懂

打开保存的文件，能否看到杯子从桌面被提起、移到托盘、松手放下？如果松手时的图像丢了，或找不到对应动作，就难以还原过程。这一层叫**结构完整性**，先确认记录器没有把过程存坏。

### 第二层：记录里的行为是否合理

文件能打开，里面的行为仍可能不合理。例如杯子放下后穿进托盘，或接触读数说“已经接触”，画面里杯子却还悬在空中。需要继续核对物理和传感器设置。

有时也要把已知的杯子三维位置投回图像，看看是否落在杯子所在的像素处；两者的差距叫**重投影误差**。这类检查帮助找到模型、计算设置或相机标定中的问题。

### 第三层：任务与标签是否说明了真实结果

重新检查杯子是否按约定松开并放稳，确认“成功”没有只看某一瞬间的位置。再看任务是否换过杯子、托盘位置和起点；始终在同一个位置成功，不能说明换个位置也能成功。

这一层还检查划分和重复数据。标签规则错了就修正规则，覆盖不足则补采对应条件，不能只增加总数量。

### 第四层：仿真证据能解释多少真实行为

在相同目标与相近初态下，比较仿真与真机的运动、接触和失败原因。这一层才回答**仿真到真实迁移（sim-to-real）**：仿真里获得的数据或能力，在真实设备上是否仍然有效，以及适用到什么范围。

每一层都留下检查结论与对应记录。这样发现问题后，能知道该修文件、改场景、调整规则，还是补充真实测试。

## Who｜谁提供测量，谁判断结果可以用于哪里？

生成数据的人说明当时怎样采集，评测的人核对任务结果，操作真实设备的人提供实际表现。小团队里可以由同一个人完成，但这些证据都需要有人提供。

<span id="5-从真实样本校准再用真机验收"></span>

例如仿真能把杯子送到托盘，杯子却在真实夹爪搬运途中滑落了，就需要测量杯子与夹爪的接触情况，再调整相应参数。用真实测量估计模型参数的过程叫**系统辨识**，也可以理解为给仿真做参数校准。

用于调参数的那几次真实尝试，不能同时拿来证明调完之后已经有效。还需要用未参与校准的任务做测试，例如另外一组杯子起点。领域随机化可以覆盖尚不确定的范围，但仍需要实测依据和真实验证。

![真实测量用于校准仿真，仿真产生与评估数据，再由未参与校准的真机任务验收](/images/docs/simulation-sim2real-loop.svg)

<span id="3-评测集隔离与可比性"></span>

## Where｜在哪里评测，数据之间怎样隔离？

先在独立保留的仿真任务上评测，再用真实机械臂检验迁移效果。用于最终评测的条件，要与训练、调参数用的条件按目标隔开，避免反复做已经熟悉的练习。

### 从划分开始，给新条件留下真正独立的测试

训练集用于学习，验证集用于调参，**留出评测集**专门留到阶段性或最终验收时使用。例如希望检验机器人能否处理新杯子，就应把选作测试的杯子与训练杯子分开，而非仅换几张图。

同一场景的相邻帧随机分到两边，可能让模型记住外观；同一条示教的扩增轨迹跨越训练与测试，也会让成绩偏高。划分时要沿着数据来源检查这些关联。

![训练、验证与留出评测按场景、资产及原始示教血缘隔离，避免相近样本跨集合](/images/docs/simulation-split-isolation.svg)

### 在同一条件下比较，结果才容易解释

比较两个策略时，让它们面对相同的杯子起点和托盘位置，才更容易看出谁表现更好。这叫**配对评估**。除了成功率，还要看失败是因为没夹住、途中滑落，还是放到托盘后倒下。

尝试次数也影响结论的可靠程度。少量尝试都成功，仍可能只是没遇到困难情况。一次放杯子的连续画面属于同一轮尝试，不能因为拍了很多帧，就当成做过很多次独立测试。

比较两个仿真器时也是如此：如果一个用更轻的杯子、更宽松的成功条件，就无法仅凭成功率判断哪个更好。应先尽量统一任务与配置，剩余差异写进报告；具体比较项目见附录。

### 真机失败时，让对照实验帮助定位原因

仿真成功、真机失败时，先找失败发生在哪一步。还没伸手就认错杯子，优先看图像；夹住后滑落，优先看接触；总是在托盘上方停不稳，再检查动作响应。附录按这些现象列出了对应的对照项目。

每次尽量只改变一类条件，例如固定初态与动作，只比较接触轨迹和力。对某些物体或布局特别差的情况，则按物体与布局分组，检查是否超出了生成范围。这样能区分模型能力问题和数据、仿真假设的问题。

<span id="2-单条-episode-和批量数据的检查"></span>

## When｜什么时候复查、进入真机测试或发布数据？

小批量采集后先检查，场景或程序变化后重新检查，发布前再汇总适用范围。只有需要判断真实表现时，仿真检查通过才是进入真机测试的起点。

### 小批量采集后，先检查一轮，再检查整体

先选一轮放杯子尝试，把夹住、移动、松手前后的图像、动作与接触读数放在一起。看它是否从允许的起点开始，过程能否连上，最后的标签能否解释实际结果。

再看整批数据。例如靠近机械臂的杯子都成功，远处的杯子却经常掉落，一个总成功率会掩盖这种差别。按杯子、起点或困难条件分组，才能知道应该补采什么。

<span id="4-复现和回归"></span>

### 引擎、模型或传感器升级后，重跑固定用例

保留一组固定的小任务，每次升级后重新运行，这叫**回归检查**。例如仍用同一个杯子、同一个起点、同一组动作，查看以前能放稳的杯子是否突然滑落，故意失败的用例是否被误判成成功。

比较前先约定允许多大数值误差，以及哪些任务行为必须保持。不同硬件、版本和并行方式可能产生数值差异，所以既要确认程序能运行，也要确认结果仍满足使用要求。

检查结果要能找回当时的程序和配置。版本变化后保留来源，使用者才能知道新旧两批数据之间发生过什么变化。

### 仿真检查通过后，分阶段做真机验收

真机测试有成本和风险，可先选代表性条件、边界条件和仿真不确定性高的任务。每次修正仿真后，固定新配置，再用未参与校准的真实任务复测，查看视觉、接触、动作延迟、轨迹与失败模式。

<span id="6-数据集发布与模型使用边界"></span>

发布时，把数据与使用说明一起交付。使用者需要知道杯子任务怎样定义、哪些条件测过、哪些记录被剔除，以及还有什么已知问题，才能判断适不适合自己的训练或评测。完整交付项目见附录。

最后明确字段可以用于策略输入、训练监督还是评估，并说明哪些结论仅在仿真中成立，哪些已经得到真实设备支持。通用方法可继续看[具身数据质量与基准评估](/guides/embodied-evaluation-data-quality/)和[合成数据与仿真到真实迁移](/guides/synthetic-data-sim-to-real/)。

## 技术附录：对照实验与发布字段

<details>
<summary>按失败现象选择配对实验</summary>

四层检查分别记录通过、拒绝或需人工复核，并附规则版本、证据与受影响的 episode ID；episode 即一轮完整任务记录。后一层的高分不能替代前一层的数据检查。

| 差异表现 | 尽量固定的条件 | 优先比较的证据 |
| --- | --- | --- |
| 真机视觉识别失败 | 动作与场景对应关系 | 仿真/真实图像、内外参、曝光、反射与分割边界 |
| 接触后滑落或装配卡住 | 初态与动作 | 接触轨迹、力、摩擦、碰撞形状、质量、夹爪力 |
| 动作迟到或振荡 | 输入观测或回放记录 | 请求与实际动作时序、控制频率、延迟、限幅、增益 |
| 特定物体或布局表现差 | 任务与评价规则 | 对应资产和布局的训练覆盖、尺寸与生成范围 |

单轮检查包括字段结构、数组与时间索引、缺失值、初态约束、初始穿透、时间单调性、观测到动作的先后关系、成功标记与结束原因。物理与传感器检查覆盖尺寸、关节限位、接触抖动、方向和标定；批量检查覆盖任务、资产、初态、随机参数、控制来源、成功失败比例、异常值、重复轨迹与拒绝原因。

跨仿真器比较应尽量统一机器人模型、目标、动作表示、控制周期、相机、结束条件与随机化分布。报告尝试次数、失败原因、超时、碰撞、人工接管与各项版本，并按独立 episode 或任务统计。成功率可附置信区间，说明计算方法与统计单位。

固定回归用例可包括自由下落、单关节响应、典型接触、成功与失败任务，检查轨迹、接触、图像尺寸、标签映射和结束原因。MuJoCo 与 MJX、或 Isaac Lab 的不同版本之间，分别验证可运行性与结果是否满足同一标准。

</details>

<details>
<summary>数据集发布摘要示例</summary>

划分至少以完整 episode 为单位，按目标隔离任务变体、资产族或场景，冻结规则与成员清单。用于真实参数校准的样本与最终真机测试样本分开。

```text
release
  dataset_id / schema_version / license
  task_manifest / scene_manifest / sensor_manifest
  engine_versions / code_commits / asset_hashes
  episode_count / duration / task_coverage
  split_manifest / quality_rule_version / rejection_summary
  benchmark_protocol / confidence_intervals
  real_world_calibration_set / real_world_holdout_result
  known_domain_gaps / approved_downstream_uses
```

仿真真值可以支持训练与分析，但评测可部署策略时，应隔离现实设备无法直接提供的信息。质量阈值、允许用途和已知差异都属于发布内容。

发布时一并交付结构说明、任务规格、资产与引擎版本、生成配置、数据划分、质量报告、许可证和已知偏差。复现记录包含代码提交、资产哈希、随机种子、硬件、并行规模和渲染设置；训练或评测结果回链到数据集、环境与策略版本，后处理图像或标签附处理版本和父数据 ID。

</details>
