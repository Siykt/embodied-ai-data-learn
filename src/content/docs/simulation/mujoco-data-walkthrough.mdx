## 具体读懂 1.00 秒这一行

状态从下标 0 开始，每隔 0.02 秒保存一次，所以 1.00 秒是 `state[50]`。它记录的角度为 `0.713746719 rad`，约 **40.89°**；实际角速度为 `0.627691235 rad/s`。

这一刻同时能看到两个目标速度，它们对应不同区间：

| 字段 | 数值 / rad/s | 对应的含义 |
| --- | ---: | --- |
| `state_ctrl[50, 1]` | 0.627691361 | 上一段 0.98–1.00 秒保持的目标 |
| `qvel[50, 0]` | 0.627691235 | 到达 1.00 秒时的实际速度 |
| `action[50, 1]` | 0.587785252 | 接下来 1.00–1.02 秒的新目标 |
| `qvel[51, 0]` | 0.587785141 | 执行这段动作后，1.02 秒的实际速度 |

因此一个可用于学习“动作怎样改变状态”的样本是：

```text
state[50]  t=1.00 s，角度=0.713746719，速度=0.627691235
action[50] 力矩通道=0，速度目标=0.587785252，保持 0.02 s
state[51]  t=1.02 s，角度=0.725502973，速度=0.587785141
```

这里的 `action` 是命令，`qvel` 是执行结果。把两者混成一列，会丢失“发了什么命令、系统实际做了什么”的差别。若要学习从当前状态预测下一状态，应配对 `state[50] + action[50] → state[51]`；`state_ctrl[50]` 用于解释这个状态采样时仍保留的控制量。

### motor 为零，为什么还会转

模型给同一个关节配置了两个执行器：

```xml
<actuator>
  <motor name="motor" joint="pivot"/>
  <velocity name="vel" joint="pivot" kv="10"/>
</actuator>
```

第一个接收直接力矩，第二个是[速度伺服](/reference/terms/#速度伺服)：根据“目标速度减实际速度”的差值产生力矩，使关节追上目标。在本模型的单位传动比下，速度执行器的力矩为 `10 × (目标速度 − 实际速度)`。所以把 `motor` 设为零，只是把第一个力矩通道设为零，速度执行器仍会驱动红杆。

## 每个字段由谁产生

| 来源 | 本例字段或产物 | 应怎样理解 |
| --- | --- | --- |
| 物理引擎 | `qpos`、`qvel`、`qacc` | 关节角、速度及当前控制下求解的角加速度 |
| 模型中的传感器定义 | `sensor_values`、`sensor_*` | MuJoCo 依据同一仿真状态计算的六类读数 |
| 采集脚本 | `action`、动作序号与映射 | 按正弦公式生成控制输入，并连接前后状态 |
| 采集脚本复制或标记 | `state_ctrl`、各类时间 | 保留采样时的控制量，并说明状态和图像对应谁 |
| 渲染器 | `overview.mp4`、`camera.png` | 从状态和场景生成的图像；不在 15 维数值传感器数组中 |
| 记录器整理 | `manifest.json` | 模型来源、版本、单位、坐标、采样规则和验收结果 |

`qpos` 和关节角传感器在本例中相等，并不代表有两个独立仪器互相验证：它们依赖同一个模拟状态，也没有额外添加测量噪声。类似地，`quat` 是引擎直接给出的姿态，不是利用陀螺仪长期积分估计出来的姿态。

## 六类传感器：名称、位置和实际读数

`sensor_values` 每行共有 15 个数。下表中的切片从 0 开始，右端不包含，例如 `[0:4]` 取第 0、1、2、3 项。表中读数均对应 **1.00 秒**。

| 名称与切片 | 单位、坐标与含义 | 该时刻的读数 |
| --- | --- | --- |
| `quat` `[0:4]` | 无量纲；IMU 相对世界的姿态，顺序 `w,x,y,z` | `(0.936994, 0, 0, 0.349346)` |
| `ang_vel` `[4:7]` | rad/s；IMU 局部三轴角速度 | `(0, 0, 0.627691)` |
| `accel` `[7:10]` | m/s²；IMU 局部三轴比力 | `(−0.019700, ≈0, 9.81)` |
| `pivot_p` `[10:11]` | rad；关节 `pivot` 的角度 | `0.713747` |
| `pivot_v` `[11:12]` | rad/s；关节 `pivot` 的角速度 | `0.627691` |
| `linvel` `[12:15]` | m/s；IMU 安装点在世界中的线速度 | `(−0.020547, 0.023724, 0)` |

三维向量均按 `x,y,z` 排列。模型没有定义磁力计，导出数据也没有磁场读数。

### 四元数的四个数怎样对应杆的方向

[四元数](/reference/terms/#四元数)用四个数表示三维旋转，四个数不能分别当成四个角度。本例只绕 z 轴转动，关系很简单：关节角为 `θ` 时，`quat = (cos(θ/2), 0, 0, sin(θ/2))`。

初始角度为零，读数是 `(1, 0, 0, 0)`；1.00 秒的 `θ = 0.713746719`，对应 `(0.936994, 0, 0, 0.349346)`。这是核对“数组切片、分量顺序和姿态定义”是否读对的一项检查，不能替代真实设备的姿态精度评估。

### 静止时，为什么加速度计不是零

初态的角速度和线速度都是零，但 `accel = (0, 0, 9.81)`。加速度计输出的是[比力](/reference/terms/#比力)，可以理解成设备受到支撑、推动等作用时感到的加速度。其关系为 `局部比力 = 将 (世界线加速度 − 世界重力) 转到传感器坐标`。

本例世界重力为 `(0, 0, −9.81)`，静止时世界线加速度为零，安装点受结构支撑，所以局部 z 轴读到 `+9.81`。这个数不表示杆在向上加速。把比力转回世界系并加上世界重力后，才得到用于描述位置变化的线加速度。

转动时，IMU 距转轴 0.05 m，需要指向转轴的向心加速度。1.00 秒时，它在局部 x 轴上的读数为 `−0.05 × 0.627691235² ≈ −0.019700 m/s²`。局部 x 轴指向杆外端，因此负号表示朝向转轴。同一时刻，世界系 `linvel` 的 x、y 都非零，表示这个安装点正在绕圆运动。

## 采样为什么决定你能看见什么

物理每 **0.002 秒**计算一步，也就是 500 Hz；动作每 10 个物理步更新，状态也每 **0.02 秒**保存一次，即 50 Hz。一个动作在这 10 步内保持不变，称为[零阶保持](/reference/terms/#零阶保持)。外部观察视频每 **0.04 秒**取一帧，即 25 fps。

![动作保持十个物理步、前后状态采样和隔一个状态取视频帧的对应关系](/images/docs/mujoco-pointer-sampling.svg)

记录器先保存初态，然后反复执行“写入动作 → 推进 10 步 → 刷新并保存状态”。保存前调用 `mj_forward`，在已保存的关节位置、速度和刚执行过的控制量上重新计算传感器与加速度。这一步避免把新状态和旧的派生读数混在一起。

因此有 **401 个状态、400 个动作**。最后 `state[400]` 是 8.00 秒的结果，没有 `action[400]`；CSV 最后一行的后续动作列为空。视频包含 200 帧，第 `j` 帧对应 `state[2×j]`，最后一帧是 7.96 秒。视频播放时长为 8 秒，不意味着它还包含一张 8.00 秒的末态图像。

`state_time` 由引擎逐步累加，`action_time` 和 `frame_time` 由序号计算。受浮点舍入影响，读取 1.00 秒可能显示 `1.0000000000000007`；应按保存的索引映射对齐，比较时间时允许很小的数值误差。

### 速度在变化，保存的 qacc 为什么几乎全为零

这是本次数据最需要留意的地方：401 行 `qacc` 的最大绝对值约为 **1.35 × 10⁻¹¹ rad/s²**。在这个很轻的杆和较强的速度伺服配置中，每段结束时实际速度已经非常接近该段目标；记录器保存的是这个端点上、仍使用上一段控制量求出的瞬时加速度。

它没有保存动作刚切换后的全部过程。以 1.00–1.02 秒为例，速度从 `0.627691235` 变为 `0.587785141 rad/s`，用速度差除以 0.02 秒得到的**区间平均角加速度**约为 `−1.995305 rad/s²`，而两个已保存端点上的瞬时 `qacc` 都接近零。这两个量描述不同的时间范围，并不矛盾。

因此这份 50 Hz 文件能解释动作与状态的连接，却不足以研究执行器响应瞬间的细节。若以后要做这类研究，需要在动作切换前后和物理步频率下额外记录控制量、加速度及执行器力矩，并重新验证采样顺序。

## 亲自读取状态编号 50

下载 [episode.npz](/data/mujoco-pointer/episode.npz)、[trajectory.csv](/data/mujoco-pointer/trajectory.csv) 和 [manifest.json](/data/mujoco-pointer/manifest.json)，放进同一目录。已有本机实验环境时，这三个文件位于 `outputs/latest.json` 指向的运行目录中。下面约十行代码可在这些文件所在目录运行，需要 Python 和 NumPy。

```python
import csv, json
import numpy as np

with np.load("episode.npz", allow_pickle=False) as d:
    k = 50
    print("当前", d["state_time"][k], d["qpos"][k], d["qvel"][k])
    print("旧控制 / 新动作", d["state_ctrl"][k], d["action"][k])
    print("下一状态", d["qpos"][k + 1], d["qvel"][k + 1])
with open("trajectory.csv", encoding="utf-8", newline="") as f:
    print("CSV 实际速度", list(csv.DictReader(f))[50]["qvel_pivot_rad_s"])
with open("manifest.json", encoding="utf-8") as f:
    print("传感器定义", json.load(f)["sensors"])
```

## 这份数据现在适合什么学习任务

**可以直接做数据读取和一致性练习。** 例如检查 `pivot_p` 是否等于 `qpos`，检查陀螺仪 z 轴是否等于 `qvel`，检查四元数是否与关节角对应，以及每个动作是否确实连接到下一个状态。这些练习让数据导出和读取错误先暴露出来。

**可以做一个有限的一步预测练习。** 输入当前关节角、实际速度和目标速度，预测 0.02 秒后的角度与速度，共能组成 400 个样本。它能演示怎样构造输入与标签；但样本只来自一条反复执行的正弦轨迹，不能据此证明模型能适应新初态、新动作或新机器人。后续应采集多条不同初态和控制序列，并按完整轨迹划分训练与评估数据。

**还不足以训练并评价抓取策略。** 场景没有夹爪、待抓物体、抓取成功条件、奖励或成功失败标记。当前动作由固定公式生成，也没有操作员示教。模仿这些动作最多复现这条旋转规律，不能产生“看见物体后抓起它”的能力。

**也不足以验证真实机器人上的传感器鲁棒性。** 当前读数无额外噪声，没有真实传感器偏置、通信延迟和丢帧样本；关节角只覆盖约 `0–0.796 rad`，速度约 `−1–1 rad/s`。若目标是真实部署，还需要对照真实设备采集这些差异，并保留未用于调参的评估数据。

## 从单关节走到机械臂，再到并行数据生成

每一步都可以沿用本页的“场景 → 控制 → 状态 → 观测 → 导出 → 验收”方法，但要补上新场景带来的数据要求。

1. **单关节：先把一条记录解释完整。** 完成本页状态编号 50 的读取练习，能说清目标、结果、单位和时间区间；再采集不同目标速度，检查读取方法是否仍成立。
2. **机械臂：让多个关节完成一次到达。** 目标可以是让末端移动到桌上指定位置。除各关节位置、速度和动作，还要记录目标位置、末端实际位置与到达误差。此时先查清数组中每个关节的名称、顺序和限位。
3. **相机：让图像与一次动作对应。** 在同一个到达任务里保存连续相机帧及其时间、内参与位姿；从一帧出发，找到当时状态、接下来执行的动作和下一帧。这是把“关节轨迹”变成“视觉动作数据”的一步。
4. **标准任务：建立可比较的成功与失败。** 用具备明确任务定义的环境学习重复重置、奖励和结束条件。让任务有多个初态，保存每次尝试为什么结束，再按相同规则评价策略。相关入口见[开源学习仓库与实践路线](/simulation/open-source-learning-repositories/)。
5. **Isaac 并行环境：在规则明确后增加采集规模。** 同时运行多个机械臂任务时，每条记录都要带环境 ID、episode ID、初态和随机化配置，避免把不同环境或重置前后的状态接在一起。先用少量环境检查动作语义、坐标、相机与成功条件，再扩大数量；具体能力与运行环境见 [Isaac Lab 与具身数据](/simulation/isaac-lab-embodied-data/)。

并行运行扩大的是样本数量。要增加可学习的信息，还必须有不同物体、初态、任务变化和失败情况，并用独立的评估轨迹检查这些变化是否带来了实际提升。

## 核对依据
